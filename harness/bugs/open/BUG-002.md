# BUG-002: Razorpay order creation client/server contract mismatch

**Bug ID:** BUG-002  
**Title:** Razorpay order creation client/server contract mismatch  
**Severity:** Critical  
**Priority:** P0  
**Feature:** FEAT-004  
**Environment:** Static source review; runtime test NOT_EXECUTED  
**Preconditions:** Customer has cart and shipping data; a sandbox checkout is configured.

**Steps to Reproduce:**
1. Submit checkout from `/shipping`.
2. Inspect request body to `/api/payment/create`.
3. Compare required body and returned fields with the client contract.

**Expected:** Server returns Razorpay order ID, currency and amount based on validated cart/pricing data; client can open checkout.

**Actual:** Client sends cartItems/shippingInfo/coupon/userId; handler requires `amount` and returns `clientSecret`, not client-expected `id`, `currency`, `amount`. Static mismatch.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (source shows request cannot satisfy handler amount check)

**Evidence:** [src/app/shipping/page.tsx](../../../src/app/shipping/page.tsx); [src/redux/api/paymentAPI.ts](../../../src/redux/api/paymentAPI.ts); [src/app/api/payment/create/route.ts](../../../src/app/api/payment/create/route.ts)

**Root Cause:** The API input/response contract is inconsistent; actual provider response was not exercised.

**Fix:** Agree server-owned payment contract and align client/backend; never accept browser amount as authoritative.

**Regression Test:** TC-012 and TC-013; add contract test for create response.

**Status:** OPEN
