# BUG-003: Order creation request omits required total fields

**Bug ID:** BUG-003  
**Title:** Order creation request omits required total fields  
**Severity:** Critical  
**Priority:** P0  
**Feature:** FEAT-004 / FEAT-005  
**Environment:** Static source review; runtime test NOT_EXECUTED  
**Preconditions:** A payment callback is reached in a sandbox test.

**Steps to Reproduce:**
1. Follow the frontend `newOrder` mutation payload.
2. Compare sent JSON with required fields in `/api/order/new`.

**Expected:** Valid order payload is accepted only after server-side amount and inventory verification; invalid/incomplete payload is rejected without partial stock effects.

**Actual:** Frontend sends `orderItems`, `shippingInfo`, `coupon`, `user`; backend requires truthy `subtotal`, `tax`, and `total` (also expects shippingCharges/discount for persistence). Static mismatch; `reduceStock` runs before create.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (source comparison)

**Evidence:** [src/app/shipping/page.tsx](../../../src/app/shipping/page.tsx); [src/types/api-types.ts](../../../src/types/api-types.ts); [src/app/api/order/new/route.ts](../../../src/app/api/order/new/route.ts); [src/utils/backend-features.ts](../../../src/utils/backend-features.ts)

**Root Cause:** Request type and route contract are inconsistent; no payment/order DB execution performed.

**Fix:** Derive totals from trusted server records, validate payload, and make inventory/order creation atomic/idempotent.

**Regression Test:** TC-012, TC-014; add regression test for no stock decrement on failure.

**Status:** OPEN
