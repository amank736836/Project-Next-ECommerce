# BUG-005: Review UI/API contract prevents the write flow

**Bug ID:** BUG-005  
**Title:** Review UI/API contract hides and misroutes review submission  
**Severity:** High  
**Priority:** P1  
**Feature:** FEAT-006  
**Environment:** Static source review; runtime test NOT_EXECUTED  
**Preconditions:** A signed-in synthetic user opens a product page.

**Steps to Reproduce:**
1. Inspect the `GET /api/product/review/[id]` JSON contract and the review button condition in `ReviewCard`.
2. Attempt to submit a review in an authorized test environment after confirming the button can be reached.
3. Inspect the RTK Query URL/method and compare with exported server route methods.

**Expected:** An eligible user can see the write control; review create/update reaches a supported API handler, persists, and recalculates the product aggregate.

**Actual:** GET returns `success` and `reviews` but no `reviewButton`, while UI renders the write button only if that field is truthy. Client POSTs to `/api/product/review/{productId}`; the dynamic route exports GET and DELETE only. The create handler is `POST /api/product/review/new`. These are static contract discrepancies; no browser/API runtime test was performed.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (source contracts statically disagree; runtime was not exercised)

**Evidence:** [ReviewCard](../../../src/components/Review/ReviewCard.tsx); [RTK Query review endpoints](../../../src/redux/api/productAPI.ts); [dynamic review route](../../../src/app/api/product/review/%5Bid%5D/route.ts); [create route](../../../src/app/api/product/review/new/route.ts)

**Root Cause:** Review response and write URL/method are inconsistent between the client and Next route handlers; eligibility behavior is not defined in the repository.

**Fix:** Align the response and write-route contract and confirm review eligibility rules in a separate product change. No application code was changed in this harness task.

**Regression Test:** TC-018 and TC-019.

**Status:** OPEN
