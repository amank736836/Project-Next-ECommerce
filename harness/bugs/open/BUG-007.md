# BUG-007: Admin API trusts caller-supplied user ID instead of verified identity

**Bug ID:** BUG-007  
**Title:** Admin API trusts caller-supplied user ID instead of verified identity  
**Severity:** Critical  
**Priority:** P0  
**Feature:** FEAT-002 / FEAT-007 / FEAT-008  
**Environment:** Static source review; runtime exploit test NOT_EXECUTED  
**Preconditions:** A test admin record exists; isolated app and synthetic caller are available.

**Steps to Reproduce:**
1. Call an admin-only endpoint without valid auth while setting `?id={knownAdminUid}`.
2. Inspect server identity verification and returned data/action.
3. Repeat with a harmless disposable mutation only when authorized.

**Expected:** Server verifies Firebase ID token/session, binds the verified principal to the role record, then authorizes the operation.

**Actual:** Admin routes generally load the query-string ID and test role; no Firebase ID token verification/binding was found. Profile creation also trusts submitted UID and assigns admin if DB user count is zero.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (design flaw visible statically; runtime exploit not run)

**Evidence:** [src/app/api/dashboard/stats/route.ts](../../../src/app/api/dashboard/stats/route.ts); [src/app/api/user/all/route.ts](../../../src/app/api/user/all/route.ts); [src/app/api/user/new/route.ts](../../../src/app/api/user/new/route.ts); [src/app/admin/layout.tsx](../../../src/app/admin/layout.tsx)

**Root Cause:** Role check is not evidence that the request caller owns the supplied UID; actual reachability/exploit requires isolated verification.

**Fix:** Implement server-side Firebase token verification and a shared auth/authorization guard; replace first-user privilege bootstrap with controlled provisioning.

**Regression Test:** TC-008, TC-021, TC-026; security regression across every admin route.

**Status:** OPEN
