# BUG-008: User and order read APIs lack caller ownership checks

**Bug ID:** BUG-008  
**Title:** User and order read APIs lack caller ownership checks  
**Severity:** Critical  
**Priority:** P0  
**Feature:** FEAT-002 / FEAT-005  
**Environment:** Static source review; runtime test NOT_EXECUTED  
**Preconditions:** Synthetic user and order records exist in an authorized isolated environment.

**Steps to Reproduce:**
1. Request `/api/user/{knownUid}` without the owner session.
2. Request `/api/order/my?id={otherUid}`.
3. Request `/api/order/{knownOrderId}`.
4. Inspect JSON for profile, address, item and payment-related data.

**Expected:** Only the owner or authorized administrator can read personal profile/order data; unauthorized requests return 401/403/404 without data.

**Actual:** User GET by ID and order GET by ID contain no caller auth/ownership check; `/api/order/my` only checks for an ID parameter and queries it.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (missing source guards; runtime exposure not tested)

**Evidence:** [src/app/api/user/[id]/route.ts](../../../src/app/api/user/%5Bid%5D/route.ts); [src/app/api/order/[id]/route.ts](../../../src/app/api/order/%5Bid%5D/route.ts); [src/app/api/order/my/route.ts](../../../src/app/api/order/my/route.ts)

**Root Cause:** Handlers return DB records based on request path/query; authentication binding is absent in those reads.

**Fix:** Enforce verified caller identity/ownership and minimize fields returned; review cache and data redaction.

**Regression Test:** TC-015, TC-027.

**Status:** OPEN
