# BUG-009: Cache invalidation uses keys different from cached product/stats data

**Bug ID:** BUG-009  
**Title:** Cache invalidation uses keys different from cached product/stats data  
**Severity:** Medium  
**Priority:** P1  
**Feature:** FEAT-001 / FEAT-005 / FEAT-007 / FEAT-008  
**Environment:** Static key comparison; Redis runtime not configured  
**Preconditions:** Redis is configured and a product/order/user mutation has occurred.

**Steps to Reproduce:**
1. Warm latest product and admin stats cache.
2. Perform a test mutation.
3. Read the corresponding endpoint again and compare against DB.
4. Repeat with Redis disabled.

**Expected:** Every mutation invalidates the exact active cache keys; data becomes fresh after the mutation.

**Actual:** Latest endpoint writes `latest-products-v2` while helper deletes `latest-products`; stats writes `admin-stats-frontend-v2` while helper deletes `admin-stats`.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (key mismatch visible; stale behavior depends on deployed Redis)

**Evidence:** [src/app/api/product/latest/route.ts](../../../src/app/api/product/latest/route.ts); [src/app/api/dashboard/stats/route.ts](../../../src/app/api/dashboard/stats/route.ts); [src/utils/backend-features.ts](../../../src/utils/backend-features.ts)

**Root Cause:** Cache write and invalidation key names differ; no TTL is set in the helper.

**Fix:** Align key constants and add Redis integration tests; consider TTL as a separate product/platform decision.

**Regression Test:** TC-024; regression coverage after product/order/user changes.

**Status:** OPEN
