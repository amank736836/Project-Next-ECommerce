# BUG-012: Unescaped catalog search is passed to Mongo regex

**Bug ID:** BUG-012  
**Title:** Unescaped catalog search is passed to Mongo regex  
**Severity:** Medium  
**Priority:** P2  
**Feature:** FEAT-001 / cross-cutting security  
**Environment:** Static source review; malformed-input runtime test NOT_EXECUTED  
**Preconditions:** Public search endpoint and isolated dataset are available.

**Steps to Reproduce:**
1. Send search terms containing regex metacharacters and bounded nested patterns.
2. Measure response/query cost and inspect Mongo behavior.

**Expected:** Search input is escaped or constrained; request length and cost are bounded; invalid terms return controlled 4xx.

**Actual:** Route inserts raw search text into `$regex` with `$options: i`; no length/rate validation is present in the handler. Exploitability/performance impact is not established.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (potential query abuse, no runtime proof)

**Evidence:** [src/app/api/product/all/route.ts](../../../src/app/api/product/all/route.ts)

**Root Cause:** Raw user input becomes a database regex; actual risk depends on MongoDB behavior, index/data shape and runtime limits.

**Fix:** Validate/escape search input and add safe boundary/performance tests after product semantics are agreed.

**Regression Test:** TC-004 and TC-028.

**Status:** OPEN
