# BUG-013: API CORS headers use wildcard origin with credentials enabled

**Bug ID:** BUG-013  
**Title:** API CORS headers use wildcard origin with credentials enabled  
**Severity:** Medium  
**Priority:** P2  
**Feature:** Cross-cutting security/configuration  
**Environment:** Static config review; browser CORS test NOT_EXECUTED  
**Preconditions:** API route response headers are enabled in a test environment.

**Steps to Reproduce:**
1. Inspect `Access-Control-Allow-Origin`, credentials and allowed headers on API responses.
2. Test browser credentialed/non-credentialed cross-origin requests from approved and unapproved origins.

**Expected:** Production CORS origins are explicitly approved; credential behavior is valid and least-privilege.

**Actual:** Next config applies `Access-Control-Allow-Origin: *` and `Access-Control-Allow-Credentials: true` to all `/api/*`; browser behavior and deployment override were not tested.

**Reproducible:** UNKNOWN / REQUIRES VALIDATION (static configuration concern)

**Evidence:** [next.config.ts](../../../next.config.ts)

**Root Cause:** Wildcard plus credentials is an unsafe/invalid policy combination for credentialed browser access; intent and actual deployment headers unknown.

**Fix:** Define allowed production origins and credential requirements; configure/verify exact response policy.

**Regression Test:** TC-027; add browser/API CORS security regression.

**Status:** OPEN
