# Requirements

Requirements here are extracted from the checked-in UI, route handlers, Mongoose models and package/configuration. They are not a signed product specification. Each requirement is assigned an `REQ-xxx` ID and mapped to a feature, scenario, case, automation status, execution result and evidence in [traceability](../reports/traceability.md).

- [Functional requirements](functional-requirements.md): observable workflows and current implementation notes.
- [Non-functional requirements](non-functional-requirements.md): repository evidence, missing targets, and `UNKNOWN / REQUIRES VALIDATION` items.
- [Business rules](business-rules.md): rules encoded in reducers, handlers and schemas, including conflicts requiring product-owner confirmation.

When UI/API behavior conflicts, record both sides instead of choosing an assumed business rule.
